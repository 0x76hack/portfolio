## 2. Agent Roles & Responsibilities

### 2.1 Orchestrator Agent
- Decomposes high-level requests into atomic sub-tasks
- Assigns tasks to the correct specialist agent
- Validates output against this file before surfacing to the user
- Resolves conflicts between agents using the **hierarchy:** Design → Accessibility → Performance → DX

### 2.2 UI/UX Design Agent
- Owns all visual and interaction decisions
- Must produce a written aesthetic rationale before generating code
- Blocked from using: Inter, Roboto, Arial, system-ui as primary typeface
- Blocked from using: purple-on-white gradients, generic hero sections, stock-style layouts
- Required to define: color tokens, type scale, spacing rhythm, motion curve — in every task

### 2.3 Frontend Engineer Agent
- Owns all React/Next.js/TypeScript code
- Follows Section 5 (Code Rules) without exception
- No `any` types. No inline styles. No `!important`
- Must run a mental lint pass before outputting code

### 2.4 Accessibility Agent
- Audits every component against WCAG 2.1 AA minimum, WCAG 2.2 preferred
- Blocks shipping if: focus order is broken, contrast ratio < 4.5:1, or ARIA is misused
- Provides remediation inline, not as a separate task

### 2.5 Performance Agent
- Targets: LCP < 1.8s, CLS < 0.05, INP < 100ms (Core Web Vitals 2025)
- Flags any component that loads a font > 40KB, image without `next/image`, or JS bundle > 50KB
- Recommends: `React.lazy`, dynamic imports, `loading="lazy"`, `fetchpriority="high"` on hero assets

### 2.6 Copy Agent
- Writes all UI text: headlines, CTAs, meta descriptions, alt text, aria-labels
- Voice: First person, active verbs, no buzzwords ("passionate", "ninja", "guru", "leverage")
- Every CTA is a concrete verb phrase: "View the case study" not "Learn more"

## 3. Design System — Pro Max UI/UX

### 3.1 Aesthetic Mandate

**This portfolio must be UNFORGETTABLE.** Choose ONE conceptual direction and execute it with surgical precision. Options ranked by suitability:

| Direction | Vibe | Font Pairing Examples |
|-----------|------|-----------------------|
| Editorial / Magazine | Ink-on-paper, considered, confident | Playfair Display + DM Mono |
| Refined Brutalist | Raw grid, typographic tension, bold scale | Bebas Neue + IBM Plex Mono |
| Soft Modernist | Warm neutrals, generous space, tactile | Recoleta + Geist |
| Dark Luxury | Deep tones, gold/cream accents, restraint | Cormorant Garamond + Neue Haas |
| Retro-Futurist | Geometric, playful precision, optimistic | Space Mono + Syne |

> **Rule:** Once a direction is chosen, every agent inherits it. No mixing.

### 3.2 Color Token Architecture

```ts
// tokens.ts — generated by Design Agent, consumed by all
export const tokens = {
  // Background layers (3 minimum, for depth)
  bg: {
    base:    'var(--bg-base)',      // Primary surface
    subtle:  'var(--bg-subtle)',    // Lifted cards, sections
    overlay: 'var(--bg-overlay)',   // Modals, tooltips
  },
  // Foreground
  fg: {
    primary:   'var(--fg-primary)',
    secondary: 'var(--fg-secondary)',
    muted:     'var(--fg-muted)',
  },
  // Brand
  brand: {
    accent:  'var(--brand-accent)',   // One bold color — used sparingly
    glow:    'var(--brand-glow)',     // Optional: light leak / halo
  },
  // Semantic
  semantic: {
    success: 'var(--success)',
    error:   'var(--error)',
  },
}
```

**Contrast law:** Every text/background pairing is checked at build time via `@radix-ui/colors`. No exceptions.

### 3.3 Typography System

- **Display (h1–h2):** Distinctive, character-forward, optically sized
- **Body:** Optimized for reading at 16–18px, line-height 1.6–1.75
- **Mono:** Used for code, labels, metadata — never for body text
- **Scale:** Modular scale with ratio 1.25 (Major Third) minimum

```css
/* Type scale — relative units only */
--text-xs:   0.75rem;
--text-sm:   0.875rem;
--text-base: 1rem;
--text-lg:   1.125rem;
--text-xl:   1.25rem;
--text-2xl:  1.563rem;
--text-3xl:  1.953rem;
--text-4xl:  2.441rem;
--text-5xl:  3.052rem;
```

### 3.4 Spacing Rhythm

- Base unit: `4px` (`0.25rem`)
- All spacing values are multiples of the base unit
- Section vertical rhythm: minimum `8rem` between major sections
- Never use arbitrary pixel values in Tailwind — use the scale

### 3.5 Motion Principles

- **Purpose-first:** Every animation must answer "what does the user learn from this motion?"
- **One hero moment:** Single, well-orchestrated page-load sequence with staggered reveals
- **Curves:** `ease-out` for entrances, `ease-in-out` for transitions, `spring` for interactive
- **Duration budget:** Entrance ≤ 600ms, micro-interaction ≤ 200ms, page transition ≤ 400ms
- **Respect:** Always implement `prefers-reduced-motion` — animations off by default for reduced-motion users

```ts
// Shared Framer Motion variants
export const fadeUp = {
  hidden: { opacity: 0, y: 24 },
  visible: { opacity: 1, y: 0, transition: { duration: 0.5, ease: 'easeOut' } },
}

export const stagger = {
  visible: { transition: { staggerChildren: 0.08 } },
}
```

### 3.6 Spatial Composition Rules

- **Negative space is content.** Crowded layouts signal insecurity.
- **Break the grid intentionally** — one element per section may violate containment
- **Asymmetry with purpose** — offset text/image, pull-quotes, oversized type
- **Depth:** Layer backgrounds (blur, shadow, translucency) to create atmosphere
- **Mobile first:** Composition is designed at 375px, then scales to 1440px+

### 3.7 Component Quality Bar

Every component must pass the **Pro Max checklist** before merge:

- [ ] Visually distinctive — would not look at home in any other portfolio
- [ ] Keyboard navigable — Tab order logical, focus ring visible and styled
- [ ] Screen-reader tested — VoiceOver / NVDA pass
- [ ] Dark + light mode — tokens swap, no hardcoded colors
- [ ] Responsive — tested at 375, 768, 1280, 1440, 1920px
- [ ] Animation respects `prefers-reduced-motion`
- [ ] No layout shift on load (images have explicit `width`/`height`)
- [ ] Hover, focus, active, disabled states all designed

## 4. Portfolio Architecture

### 4.1 Page Structure

```
/                    → Hero + Featured Work + Brief About + CTA
/work                → Project grid / list
/work/[slug]         → Case study (problem → process → outcome)
/about               → Longer narrative, values, skills, timeline
/contact             → Single focused form or direct links
```

### 4.2 Hero Section — Non-negotiable Rules

- Loads in under 1.8s on 4G (Core Web Vitals: LCP)
- Contains: Name, one-line role descriptor, one primary CTA
- Does NOT contain: Skills lists, technology badges, social proof stats, stock imagery
- Typography is the hero — not a photo, not an illustration, not a video background
- First meaningful paint shows real content, not a loading skeleton

### 4.3 Case Study Template

Each project page follows this arc — no exceptions:

1. **Context** — What was the problem? Who was affected?
2. **Constraints** — Time, team, technology, business requirements
3. **Approach** — What did you explore? What did you discard and why?
4. **Craft** — The actual work: code, design, decisions
5. **Outcome** — Measurable results, lessons, what you'd do differently

> Case studies without outcomes are CVs. Outcomes are required.

### 4.4 Navigation Patterns

- **Desktop:** Minimal top nav — max 5 items, no dropdowns
- **Mobile:** Off-canvas or fullscreen overlay — touch targets ≥ 48×48px
- **Active state:** Unambiguous — not just a color change
- **Scroll behavior:** Sticky header with blur backdrop, reduces opacity on scroll

## 5. Code Implementation Rules

### 5.1 Language & Style

- TypeScript strict mode — `"strict": true` in `tsconfig.json`
- No semicolons
- No `any` — use `unknown` and narrow with type guards
- Early returns over nested conditions
- `const` over `function` declarations for components and handlers
- Descriptive names: handlers prefixed `handle`, booleans prefixed `is`/`has`/`can`

```ts
// ✅ Correct
const handleProjectClick = (slug: string) => {
  if (!slug) return
  router.push(`/work/${slug}`)
}

// ❌ Wrong
function click(s) {
  router.push('/work/' + s);
}
```

### 5.2 React / Next.js

- App Router only — no Pages Router
- Server Components by default — opt into `'use client'` only when necessary
- `next/image` for every image — no raw `<img>` tags
- `next/font` for every font — no Google Fonts CDN links
- `next/link` for internal navigation — no `<a href>`
- Metadata API for every page — title, description, OG image

### 5.3 Styling

- Tailwind classes only — no inline styles, no CSS modules, no styled-components
- CSS variables for design tokens — defined in `globals.css`, consumed via Tailwind config
- `class:` pattern for conditional classes over ternary operators
- Responsive prefix order: base → `sm:` → `md:` → `lg:` → `xl:` → `2xl:`

### 5.4 Accessibility Code Patterns

```tsx
// Interactive non-button elements
<div
  role="button"
  tabIndex={0}
  aria-label="View project: E-Commerce Redesign"
  onClick={handleProjectClick}
  onKeyDown={(e) => e.key === 'Enter' && handleProjectClick()}
>

// Images
<Image
  src={project.image}
  alt={project.imageAlt}  // Never empty for meaningful images
  width={800}
  height={450}
  priority={isAboveFold}
/>

// Form fields
<label htmlFor="email-input">Email address</label>
<input
  id="email-input"
  type="email"
  aria-required="true"
  aria-describedby="email-error"
/>
```

### 5.5 Commit Convention

Format: `<type>[optional scope]: <description>`

Types: `feat` · `fix` · `refactor` · `style` · `perf` · `a11y` · `docs` · `chore` · `test`

```
feat(hero): add staggered text reveal animation
perf(images): convert PNG assets to WebP with next/image
a11y(nav): implement skip-to-content link and ARIA landmarks
fix(contact): correct focus trap in modal on mobile Safari
refactor(tokens): consolidate color variables into single token file
```

## 9. What Good Looks Like

> Agents refer to these reference-quality benchmarks when evaluating their own output.

**Typography:** Feels like a type designer made every choice — scale, weight, tracking, leading all considered  
**Color:** Immediately recognizable palette — someone could describe it in one sentence  
**Motion:** Enhances understanding, never distracts — you'd notice if it was missing  
**Copy:** Every word earns its place — removing any word would lose meaning  
**Code:** A senior engineer would be proud to have written it — readable, typed, tested  
**Accessibility:** A screen reader user and a keyboard-only user have an equivalent experience  
**Performance:** Feels instant — users on 4G in Chennai don't wait
